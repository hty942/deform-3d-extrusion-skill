# 材料

## 1. 塑性体必须有流动应力数据

DEFORM 需要 σ = f(ε, ε̇, T) 的表或本构模型。只给弹性模量/泊松比，算出来的是错的。
材料来源优先级：

1. 随安装的材料库 `D:\Program Files\SFTC\DEFORM\v11.0\MaterialLibrary\Standard\`
2. 厂商算例自带的材料 KEY（挤压算例目录里）
3. 文献数据 → `scripts/make_material.py` 生成 KEY

## 2. 铝合金的坑（本机实测，2026-11 复核）

- 安装目录里**确实有一个 6060 条目**：`6060_s000001.KEY`，MTNAME 为 `6060-thermo-verified`
  （2026-09-29 创建，不是原厂安装自带）。**但它的 FSTRES 表与
  `ALUMINUM-6061[500-900F(260-480C)]_s` 的 68 个数值逐个相同**（本机逐值比对，差异为 0）。
  也就是说：这是把 6061 数据改名成 6060，**不是独立的 6060 实测数据**。
  用它可以，但报告里必须写"6060 采用 6061 流动应力表代用"，不能写成"实测 6060"。
- 本机 `dof_c1` 算例实际用的材料名是 `AA6060_EXISTING_TABLE_UNVERIFIED`，其 FSTRES 与上述两套表也**完全一致**。
- `AL-6063,COLD[70-480F(20-250C)]` 的厂家等效牌号是 DIN AlMgSi0.5（3.3206，即 6060），但**数据只到 250 °C**，
  450～500 °C 热挤会外插 230 °C，不可信。
- 可用的高温数据：
  - `ALUMINUM-6061[500-900F(260-480C)]`（到 482 °C）
  - `ALUMINUM-6082[570-930F(300-500C)]`（到 500 °C，温度网格最全）
- 代用必须写进报告：为什么选它、和 6060 的差异。
- **怎么自己核对**：把两个材料 KEY 的 `FSTRES` 段数字抽出来逐值比较（本仓库就是这么发现"6060"其实是 6061 的）。
  名字不同不代表数据不同，反过来也一样。
- **T6 不是输入参数**：它是成品状态；挤压仿真里流动应力只与温度/应变速率/应变有关。

## 3. 单位制核对

材料库同时有 `_s`（SI）与 `_e`（English）版本。关键数值对照（6061）：

| 关键字 | SI | English |
|---|---|---|
| `YOUNG` | 68947 | 10000 |
| 温度点 | 260 / 371 / 482 | 500 / 700 / 900 |
| `FSTRES` 首行 | 41.369 | 6.0 |

同一材料两版差 6.894757 倍（ksi→MPa）。用之前先看后缀。

## 4. 用脚本生成材料

```bash
python scripts/make_material.py --config mat.json --out AA6060.KEY
```

`mat.json` 支持三种来源：

- `henshel`：Hensel-Spittel 本构参数
- `arrhenius`：双曲正弦 Arrhenius（A, α, n, Q）
- `table`：显式 σ-ε 曲线表（多温度、多应变速率）

脚本内置物理合理性检查：应力必须随温度下降、随应变速率上升；不满足会警告。

生成后在 Pre 里 `Material → Load from File` 载入，或直接把 KEY 里的 `FSTRES` 块并入算例 KEY。

## 5. 刚性件

模具/挤压筒/挤压杆用 **Rigid**，不需要流动应力。若要做模具应力/磨损分析，才改成 Elastic 并走 Die Stress 流程。

## 6. 热物性

热挤要勾 Heat transfer 时，材料还需：导热系数、比热、热膨胀（可选）。材料库条目一般自带；自建材料时别漏。
